# kr3-responsive-shop — адаптивный магазин Shop_ot_bob

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Дисциплина: «Фронтенд и бэкенд разработка».

## Описание

Shop_ot_bob — учебный интернет-магазин рук для армрестлинга и повседневных задач.
Проект — адаптивная версия многостраничного HTML/CSS-сайта из контрольной работы №1.

Bootstrap и другие CSS-фреймворки **не используются**: сетки, медиазапросы, формы и таблицы
написаны вручную на Flexbox и CSS Grid.

## Страницы

На каждой странице в `<head>` есть `viewport` и оба файла стилей в правильном порядке:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<link rel="stylesheet" href="css/style.css">
<link rel="stylesheet" href="css/responsive.css">
```

`responsive.css` идёт вторым: при одинаковой специфичности побеждает правило, объявленное позже,
поэтому адаптивные правила переопределяют базовые.

## Адаптивные решения

- добавлен отдельный файл `css/responsive.css`;
- применён подход **Mobile First**: правила без медиазапросов описывают телефон,
  дальше страница расширяется через `@media (min-width: ...)`;
- контрольные точки: `640px`, `768px`, `900px`, `1024px`, `1280px`;
- навигация, hero-блок, кнопки, подвал — **Flexbox**;
- сетки карточек, каталог с боковым фильтром, страница товара, формы, контакты — **CSS Grid**;
- в сетках используется `minmax(0, 1fr)`, чтобы длинное содержимое не распирало колонку;
- длинные слова переносятся (`overflow-wrap: anywhere`);
- горизонтального скролла всей страницы нет ни на одной ширине.

### Responsive images

- базовое правило `img, video { max-width: 100%; height: auto; }`;
- у всех изображений заданы `width` и `height` — страница не «прыгает» при загрузке;
- **карточки товаров** — `srcset` с тремя размерами (320, 480, 640 px) и `sizes`,
  браузер сам выбирает подходящий файл;
- **формат WebP** подключён через `<picture>` и `<source type="image/webp">`, JPEG остаётся запасным вариантом;
- **hero-блок** — разные изображения для разных экранов (art direction):
  на телефоне вертикальный кадр `hero-tall-*`, на планшете и desktop — широкий баннер `hero-wide-*`;
- **страница «О нас»** — `srcset` с плотностью `1x` / `2x`;
- изображения ниже первого экрана загружаются лениво (`loading="lazy"`).

Исходные PNG из КР №1 (до 1,4 МБ) заменены на оптимизированные файлы: вся папка `images/` весит около 1,2 МБ.

### Формы

- на телефоне все поля идут в одну колонку, с 768px — в две, широкие поля занимают всю строку;
- поля не выходят за экран (`width: 100%`, `min-width: 0` у ячеек сетки);
- высота полей и кнопок не меньше 44px, размер шрифта 16px (iOS не увеличивает страницу при фокусе);
- кнопки переносятся и не слипаются (`flex-wrap`, `gap`);
- у каждого поля есть `label`, связанный через `for` / `id`.

### Таблицы

- таблицы обёрнуты в `.table-wrapper` с `overflow-x: auto` — прокручивается сама таблица, а не страница;
- у широкой таблицы сравнения задан `min-width: 640px`;
- на телефоне таблица сравнения превращается в карточки (см. «Самостоятельные доработки»);
- узкие таблицы из двух колонок (характеристики, часы работы) помещаются без прокрутки.

### Модальное окно

- ширина `min(100% - 32px, 560px)` — окно не выходит за экран;
- высота ограничена `100dvh - 32px`, длинная форма прокручивается внутри окна.

## Доступность

Исправления по итогам ручной проверки и Lighthouse:

- **ссылка пропуска** «Перейти к основному содержимому» — первый элемент страницы, появляется по `Tab`;
- **видимый фокус** `:focus-visible` на всех ссылках, кнопках и полях; на синих кнопках обводка двойная, чтобы её было видно;
- **контраст**: серый текст `#8a8a8a` (3,5:1) заменён на `#595959` (7:1); метка на карточке — тёмный текст
  на светлом фоне вместо белого на оранжевом; зелёный текст «В наличии» затемнён; рамки полей — `#767676` (3:1);
- **`iframe` с картой** получил `title`;
- **`alt`** у изображений переписаны: описывают, что нарисовано; исправлены неверные описания у товаров «Грация»;
- **`title`** у каждой страницы свой и осмысленный;
- текущая страница в меню отмечена `aria-current="page"` и выделена не только цветом;
- у ссылок «Подробнее» и кнопок «Заказать» есть `aria-label` с названием товара;
- **формы**: подсказки и ошибки связаны с полем через `aria-describedby`; текст ошибки появляется под полем,
  поле получает `aria-invalid`, фокус переходит на первое поле с ошибкой; обязательные поля отмечены `required` и звёздочкой;
- сообщение об отправке выводится в область `role="status"`;
- **таблицы**: добавлены `caption`, `scope="col"` и `scope="row"`;
- **модальное окно** сделано на `<dialog>`: фокус не уходит за окно, `Esc` закрывает его, после закрытия фокус
  возвращается на кнопку, с которой окно открыли; у крестика есть `aria-label`;
- учтена настройка `prefers-reduced-motion`;
- ARIA используется только там, где не хватает обычного HTML.

Семантика: на каждой странице один `h1`, заголовки идут по порядку, навигация размечена через `nav`
с `aria-label`, для действий — `button`, для переходов — `a`.

## Lighthouse

Проверка: Lighthouse 13.6, категория Accessibility, мобильный режим.

| Страница | До исправлений | После исправлений |
|---|---|---|
| `index.html` | 91 | 100 |
| `catalog.html` | 96 | 100 |
| `order.html` | 96 | 100 |

Что нашёл Lighthouse до исправлений:

- недостаточный контраст текста и фона (`color-contrast`) — на всех страницах;
- у `iframe` с картой нет `title` (`frame-title`) — на главной и в контактах.

Файлы в папке `lighthouse/`:

- `accessibility-report.png` — скриншот отчёта для `index.html`;
- `accessibility-catalog.png`, `accessibility-order.png` — скриншоты для каталога и формы;
- `before/` — HTML-отчёты до исправлений;
- `after/` — HTML-отчёты после исправлений.

Lighthouse проверяет только то, что можно проверить автоматически. Порядок фокуса, понятность
`alt`-описаний и работа с клавиатуры проверяются вручную: проход по странице клавишей `Tab`,
открытие и закрытие модального окна, отправка форм с ошибками и без.

## Самостоятельные доработки

1. **Мобильное меню.** Кнопка «Меню» с `aria-expanded` и `aria-controls`, значок превращается в крестик.
   Меню закрывается по `Esc` (фокус возвращается на кнопку), по щелчку вне шапки и при переходе на широкий экран.
   Шапка «прилипает» к верху экрана. Без JavaScript меню просто остаётся развёрнутым.
2. **Каталог.** Рабочий фильтр: поиск по названию, категория, для кого, сторона, цена, наличие.
   Сортировка по цене и названию. Счётчик «Найдено: N товаров» озвучивается скринридером.
   На телефоне и планшете фильтр сворачивается под кнопку, на desktop — липкая боковая колонка.
   Категорию можно передать в адресе: `catalog.html?category=sport`.
3. **Таблица в виде карточек.** На экранах уже 640px таблица сравнения перестраивается: каждая строка —
   отдельная карточка, название колонки подставляется из `data-label`. Прокрутка вбок не нужна.
4. **Изображения.** WebP с запасным JPEG, три размера через `srcset` / `sizes`, разные кадры для hero через `picture`,
   `1x` / `2x` на странице «О нас».
5. **Страница товара по id.** `product.html?id=N` показывает любой из 8 товаров: название, цену, фото
   (вместе с `srcset`), описание и таблицу характеристик.
6. **Сводка заказа.** На `order.html` считается сумма с учётом количества и доставки;
   товар подставляется из адреса `order.html?product=N`.
7. **Кнопка «Наверх»**, появляется после прокрутки на экран.
8. **Стили для печати** — без меню, фильтра и кнопок.
9. Улучшенная доступность: ссылка пропуска, двойной фокус на тёмных кнопках, доступные ошибки форм,
   доступное модальное окно, `prefers-reduced-motion`.
